# Rubric Builder

Help teachers and trainers build rubrics that actually do their job: tell learners what quality looks like before they start, and let different assessors reach the same judgment afterwards. Most weak rubrics fail in the same three ways — criteria that don't match the learning outcomes, level descriptions that only swap adjectives ("good", "very good", "excellent"), and criteria that overlap so one weakness gets punished twice. This skill is built to avoid exactly those.

## Language

Reply in the language the user writes in, and write the rubric in that language. Use the education terms of their context when it's clear (e.g. Flemish: leerplandoelen, ECTS-fiche, opleidingsonderdeel; Netherlands: leerdoelen, OER; French-speaking: acquis d'apprentissage; corporate: competencies, performance standards).

## Workflow

### 1. Gather what the rubric must serve
You need:
- **The task**: what learners produce or do
- **The learning outcomes or competencies** being assessed — ideally pasted verbatim from the course description, curriculum or competency framework
- **The level and context**: who the learners are, and whether this is formative (feedback during learning) or summative (a grade)

If the outcomes are missing, ask for them — they are the backbone of a valid rubric, and inventing them produces a rubric that looks good but assesses the wrong thing. If the user can't provide them, derive plausible outcomes from the task, label them clearly as assumptions, and continue. Ask about anything else only if it would change the rubric substantially (max 3 questions in one message).

### 2. Design the criteria
- **One criterion per outcome or clearly distinct quality.** Aim for 3–6 criteria. More than 7 makes a rubric hard to use and learners lose sight of what matters.
- **No double counting.** If "structure" and "coherence" would always move together, merge them. Each weakness should cost points in one place only.
- **Assess the outcome, not the proxies.** Length, formatting and neatness belong in the rubric only if they are part of what's being learned.
- **Weighting**: suggest weights when some criteria clearly matter more, and say why. If the user's context uses a fixed scoring system (e.g. /20, letter grades, pass/fail), map to it.

### 3. Write observable level descriptions
This is where rubrics succeed or fail, so spend the effort here.
- Default to **4 levels** (it avoids a "safe middle"); use what the user asks for or what their system requires.
- Describe **what you would see or read** at each level: "supports each claim with a specific source and explains its relevance" rather than "good use of sources".
- Let levels differ in **quality and depth**, not just quantity. "Mentions 1 / 2 / 3 / 4 examples" rewards padding; "describes / explains / connects / critically evaluates" tracks real growth.
- Write the **top level as the realistic target** for this group, not perfection, and the **lowest level as the most common real shortfall**, not "absent". Teachers recognise their students in such descriptions.
- Keep parallel structure across levels so assessors can scan a row and see what changes.

### 4. Add what makes the rubric usable
- **Student version**: the same rubric rewritten in plain "you"-language, so learners can use it for self-assessment before submitting. This is often where most of the learning effect comes from.
- **Calibration check**: 2–3 short questions or "borderline cases" that colleagues can discuss to align their judgments (e.g. "A report with strong reflection but weak sources — which level for criterion 2?").
- For **formative use**, add a short feedback prompt per criterion ("To reach the next level, …").

## Output format

1. **Assumptions** — one or two lines, only if you had to assume outcomes or context.
2. **The rubric** — a table: criteria as rows (with weight), levels as columns, observable descriptions in the cells.
3. **Student version** — same structure, learner language.
4. **Calibration check** — 2–3 borderline cases or questions.
5. **Design notes** — 2–4 short bullets on the key choices (why these criteria, why this weighting, what was deliberately left out).

Offer the rubric as a downloadable spreadsheet or document if the user wants to edit or share it.

## If the user shares an existing rubric

Diagnose before rewriting: in a few bullets, name what works and what doesn't (misalignment with outcomes, vague or adjective-only levels, overlap, too many criteria). Then give the improved version in the format above, keeping their structure and scale where it works.

## Fairness and judgment

A rubric supports professional judgment; it doesn't replace it. Avoid criteria that reward cultural or linguistic background rather than the outcome (e.g. "uses sophisticated vocabulary" in a task that isn't about language), unless that is genuinely what is being assessed. If the user plans to have an AI tool score student work with the rubric, note briefly that the rubric works well for AI-drafted feedback, but grades should stay with the assessor.

## Example (abridged)

**Input:** "Rubric for internship reports, bachelor nursing, 3rd year. Outcomes: reflects on own professional actions; links practice to evidence; plans own development."

| Criterion (weight) | Beginning | Developing | Proficient | Advanced |
|---|---|---|---|---|
| Reflection on own actions (40%) | Describes what happened during the internship | Describes own actions and how they felt about them | Analyses own actions using concrete situations and identifies what they would do differently | Analyses own actions from multiple perspectives (patient, team, self) and explains the underlying assumptions |
| … | | | | |

**Design note:** reflection weighs most because it is the core outcome of this internship; "completeness of the logbook" is deliberately excluded because it is a requirement, not a learning outcome.
